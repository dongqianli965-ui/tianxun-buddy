# V4.2.5.1 安全缺陷修复报告

本轮完成 OCR 人工复核工作流、权限边界、提交与审批内容绑定、来源/原件/页图哈希锚定、审计链完整性检查及事务回滚保护。EDITOR 不能审批，REVIEWER/OWNER 才能审批或退回；审批要求提交版本、内容 SHA256、期望版本和人工确认。

修复前 ACL 证据：`reports/v426/acl_pre_fix.log`，20 failed / 17 passed，复现 EDITOR 越权审批及有效 REVIEWER 被拒等缺陷。修复后 ACL 回归：`reports/v426/ACL_REGRESSION.log`，54 passed / 0 failed；OCR 组合回归 69 passed。最终全量后端隔离回归 `FINAL_RESULT.json` 为 1036 passed / 0 failed / 0 skipped；前端构建与浏览器 4 项回归全部通过。

Store 侧增加内容、来源、资产、链头、事件绑定和安全事件 sidecar 表，并保留失败回滚与 legacy 历史不可自动包装为可信的保护。迁移只在隔离样本库/PoC 中验证，未迁移生产 PostgreSQL。

交付结论：安全修复代码和回归证据可交付；生产验收为 `false`，正式工程造价精度 E 为 `BLOCKED`。

## 独立复核与复现位置

| 检查项 | 实际位置与复现方式 | 结论及修复 |
|---|---|---|
| 编辑/复核权限混淆 | `backend/txbuddy/governance/api.py::save_review`；用 EDITOR 向旧 `/reviews` 提交 REVIEWED，用 REVIEWER 提交相同决定；失败证据 `acl_pre_fix.log` | 真实缺陷，按业务动作分别检查 WRITE / REVIEW；增加 `/drafts`、`/submit`、`/decisions` |
| 请求字段及版本绕过 | `save_review`、`submit_review`、`decide_review`；伪造状态、附加内容、旧提交版本或内容哈希 | 请求模型拒绝额外字段；提交不得夹带内容修改；审批绑定当前版本、提交版本与内容哈希 |
| 历史损坏后继续写入 | `backend/txbuddy/governance/ocr_review.py::ReviewStore.save`、`_integrity_issues`；在隔离库修改事件、删中间/尾事件、改内容/序号/前序哈希 | 真实缺陷；同一事务先验证原件、页图、资产锚、全部事件、版本及链头，异常拒绝追加，回滚后记录安全事件 |
| 并发及中途失败 | `ReviewStore.transaction`、`save`；8 个并发写入争用相同版本，或在事件插入后注入异常 | 仅 1 个并发请求成功，其余版本冲突；事件、绑定及链头一起回滚，恢复后可继续追加 |
| 重复 OCR 来源 | `ReviewStore._register_content`、`scripts/v426_ocr_dedup.py`；重建实际 40 条来源登记 | 33 个独立内容、40 条来源保留，复用 7 次；跨不同 requested_pages 的引擎级去重仍待开发 |
| 跨项目和无效 Token | `get_page`、`require`、现有 security runtime；无成员用户访问页面/页图/写接口，以及无效 Token 直接调用 API | 测试拒绝未授权请求；保留现有项目 ACL，不自动补齐 OWNER，owner-claim 行为回归通过 |
| 普通复核冒充专业签认 | `professional_signoff`、`ReviewStore.save`；普通 REVIEWER/OWNER 请求 signoff，或在编辑字段伪造资质 | 服务器要求 verified_professional 身份与资质登记；预留签认字段由服务端注入，普通角色不能绕过 |

对应测试为 `backend/tests/test_v426_ocr_acl.py`、`test_v426_ocr_store.py` 和既有 `test_v425_ocr_review.py`。角色用真实 ASGI API 请求验证，浏览器角色流程在隔离 TEST_ONLY 身份和数据库运行；这不构成真实人工复核记录。

## 保护边界

SQLite 文件控制者可以删除触发器、改写数据库及哈希锚，本轮保护不等于抵御所有数据库所有者级攻击。已有未锚定且非空的旧复核历史不得自动包装为可信；原件或页图变化、链损坏时须独立调查。本轮未迁移生产数据库，没有伪造人工复核或专业签认。打包负向与一致性回归实测 21 passed，日志见 `reports/v426/PACKAGE_TESTS.log`。
